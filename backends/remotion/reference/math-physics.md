# 数学 / 物理教学片（math-physics）

> 题材包：在既有「黑底 MG 讲解片」体系上加**数学与物理**的画法。
> 配 `template/src/math.tsx`（图元库）、`template/src/formula.tsx`（真 LaTeX 公式）、`template/scripts/gen_mathjax_svg.mjs`（构建期公式生成器）。
> 本文的数字都是**实测反推**的（探针 8 种原型 + 照搬 `frame_metrics.py` 算法测量），不是估计值。

## 0. 何时用 / 何时不用

**适合**：讲概念、直觉、量级、因果——「傅里叶在干什么」「为什么电场线长这样」「矩阵乘法为什么这么算」「这个积分代表什么」。
数学/物理在这套体系里**能拿到比纯抽象题材更好的效果**：图元天生自带结构，配音 + 字幕 + 大数字主角组合起来比 Manim 的无声动画更适合科普。

**不适合**：
- **严格推导 / 逐步证明 / 公式变形为主**的片子。这套体系「一句解说 = 一个镜头」，推导需要「连续演算十几秒不切、停下来盯一步看」的节奏，且每步推导没有大数字可当主角 → 会被自己的 QC 判据反复判不合格。这类内容建议用 Manim（真 LaTeX 排版 + `Axes.plot` + `Transform` + 3D）。
- 需要真 3D 场景的题材（本图元库只有 `TiltPlane` 的假纵深）。
- 需要交互式探索的内容。

## 1. 图元库（`src/math.tsx`）

镜头里这样导入（`src/shots/Gn/SCxx.tsx`）：

```tsx
import {Axes, Plot, ParamCurve, MovingPoint, SecantTangent, AreaFill, VectorField,
        AngleArc, RightAngle, TickMark, Polygon, GlowDot, SpanLabel} from '../../math';
import type {AxesSpec} from '../../math';
```

| 图元 | 用途 | 关键参数 |
|---|---|---|
| `Axes` | 坐标系：轴 + 刻度 + 数值标签 + 可选网格 | `AxesSpec`、`ticks`、`grid`、`xLabel/yLabel`、`p` |
| `Plot` | 函数曲线 y=f(x) | `axes` `f` `samples` `p` `glow`（⚠ 光晕是紫的，见 §3 规则 2） |
| `ParamCurve` | 参数曲线 (x(t),y(t))：圆/椭圆/摆线/相图 | `axes` `x` `y` `t0` `t1` `p` |
| `MovingPoint` | 曲线上的动点 + 到两轴的虚线投影 | `cx` `cy` `dropLines` `glow` `label` |
| `SecantTangent` | 割线 → 切线极限 | `f` `fp` `x0`、`dx(n)` 随帧递减 |
| `AreaFill` | 曲线下面积 + 黎曼矩形 | `a` `b` `rects` `activeRect` |
| `VectorField` | 向量场（箭头阵） | `cols/rows` `vec`（画布像素进、向量出）`activeAt` |
| `AngleArc` / `RightAngle` / `TickMark` | 角弧 / 直角符号 / 等长刻度 | 几何标注三件套 |
| `Polygon` | 多边形 + 顶点标签 | `pts` `labels` |
| `GlowDot` / `SpanLabel` | 发光点 / 区间标注 | — |

统一约定：**纯函数、确定性、`p` 是 draw-on 进度**（0→1）。全部按「白描边 2–3px + 黑填充 + 网格 `#4A4A4A` 1px + 最小字号 22px」实现。

### 尚未实现（做对应题材前需先补）
- `FieldLines`：偶极子 / 平行板的**场线**（当前 `VectorField` 只覆盖均匀与径向箭头场）
- `Scope`：示波器外壳（网格 + 波形框 + 扫描游标）
- 电路元件图元：`Battery` / `Resistor` / `Capacitor` / `Wire` / `Switch`（当前需在镜头里手画）

## 2. 真 LaTeX 公式（`src/formula.tsx`）

```tsx
import {MathFormula, MathFormulaReveal, FORMULA_NAMES, formulaTex} from '../../formula';

<MathFormula name="fourierSeries" fontSize={40} />
<MathFormula name="maxwellFaraday" fontSize={40} color={PURPLE_LIGHT} glow="drop-shadow(0 0 12px rgba(102,45,248,.9))" />
<MathFormulaReveal N={N} f0={120} name="ftc" fontSize={44} />        // 左→右"写出来"
```

**管线**：`scripts/gen_mathjax_svg.mjs` 在**构建期**用 MathJax 把 TeX 转成**自包含 SVG**（字形是矢量路径内嵌在 `<defs>`），写进 `src/common/mathjax_svg.ts`（已提交）。运行期因此：
- **不需要 LaTeX**、**不需要字体文件**、**不访问网络**
- 同一帧渲染**逐字节可复现**
- **零运行时代价**——40MB 的 `mathjax-full` 只是 devDependency

**加新公式**：把 TeX 加进脚本的 `FORMULAS` → `npm i && node scripts/gen_mathjax_svg.mjs` → 提交生成物。

**三条操作要点**：
1. **配色**走 SVG 的 `currentColor` → **设外层 div 的 `color`**，不要改 SVG 内部。
2. **缩放**走根 `<svg>` 的 `ex` 单位 → **设外层 div 的 `fontSize`**，不要覆盖 svg 的 width/height。
3. 同一帧**可以安全渲染多条公式**：每条公式的 SVG id 前缀唯一（`MJX-1`…`MJX-N`）且内部自洽。

**已入库 46 条**（代数 / 微积分 / 三角复数 / 傅里叶 / 电磁 / 波与量子 / 线性代数 / 排版疑难）。写分镜时用 `FORMULA_NAMES` 核对键名，用 `formulaTex(name)` 取出 TeX 源码做事实核对。TeX 若不在库里，**先加进生成器再加分镜**——不要让构建组自己拼。

### 尺寸标定（实测）

**嵌套分式的墨迹高 ≈ 2.59 × fontSize**（18→47、24→62、32→83、44→114，比值完全线性）；**单层公式 ≈ 1.2 × fontSize**。

| 目标档位（沿用 `composition-and-light.md` 尺寸速查） | 嵌套分式 | 单层公式 |
|---|---|---|
| 图内正文 / 公式主项 ink ≥48px | fontSize ≥ 19（但受 22px 字号下限约束，**取 ≥22**） | ≥ 40 |
| 结果项 ink ≥72px | ≥ 28 | ≥ 60 |
| 大字 ink ≥96px | ≥ 37 | ≥ 80 |
| **主角 ink ≥170px** | **≥ 66** | **≥ 142** |

> **推论（重要）**：规范要求「主角 ≥170px 且必带光」，公式题材**可以直接满足**——把公式放大到 66px（嵌套）/142px（单层）就是合法主角，不必绕道"外挂一个大数字"。

## 3. ★ 四条硬规则（实测反推）

### 规则 1：数学图元当主角看「图形尺寸」，不看线条多少

| 图元 | 实测主体尺度 | 能否当主角（≥170） |
|---|---|---|
| 坐标系图卡（w566×h372） | **481** | ✅ |
| 几何图形（三角形高约 340） | **370** | ✅ |
| 电路（高约 300） | **313** | ✅ |
| **向量场 / 场线阵**（12×7 箭头） | **141** | ❌ |
| **单个数学符号大字**（如 `∮` 124px） | **141** | ❌ |

场线、网格、箭头阵、单符号**天然当不了主角**（个体太小，`frame_metrics` 的 41px 横向膨胀也并不到一起）。必须外挂一个 ≥170px 的实体（**点电荷大圆 r≥95**、**坐标系图卡 h≥372**）或**多位数字**的大字，场线降为配角环绕。
> **实测验证**：给向量场加一个 r=95 的点电荷圆（描边白 3px）后，主体尺度由 **141 → 210**，**主角尺寸过关**。
> ⚠ 单个符号（`∮`/`∑`）当大字**不够**（实测 141）——要用**多位数/多字**。

### 规则 2：紫色预算是硬约束，而且被"规范自己要求的紫硬投影"先吃掉大半

`frame_metrics.py` 的紫色碎片 = `(b>r)&(r>g)&(sat>0.45)&(lum>45)`，膨胀 7×25 后 **≥80px 的块计数**，**≥8 判 `低:紫色碎片≥8`**。实测来源拆解：

| 来源 | 块数 | 说明 |
|---|---|---|
| **标题的紫硬投影**（`CText shadow="4px 4px 0 PURPLE"`） | **2** | `composition-and-light.md` 强制「硬投影是'重'字的标配」 |
| **大数字的紫硬投影**（`BigNumber` 默认 `6px 6px 0 PURPLE`） | **3–4** | 同上 |
| **高不透明度的紫色 `drop-shadow` 光**（如 `drop-shadow(0 0 14px rgba(102,45,248,.85))`） | **1–3** | ⚠ 实测：`.85` 不透明度合成后亮度约 **72 > 45**，**会被算作紫色碎片**（给点电荷圆加紫 drop-shadow 后碎片从 6 飙到 15）。要发光就用 **低透明度柔光（`HeroGlow` / `GlowBlob`，.35–.45）或白光晕** |
| 紫色实心图元（紫色动点 / 当前矩形 / 当前向量） | 1 | 「紫只给当前重点」 |
| 紫色小字 / 紫色 glyph | 1 | 可改 `GREY` |
| **`Plot glow` 的紫光晕**（`sw*2.4` 紫描边，不透明度 .35 → 亮度≈87 > 45） | **1（大块）** | ⚠ 最容易漏算 |
| 紫色柔光（`HeroGlow` / `GlowBlob`，alpha .35–.45） | **0（通常）** | 亮度通常 <45；但多图层叠处可能压线，边界情况看实测 |

**规则**：标题紫硬投影(2) + 大数字紫硬投影(3–4) 已占 **5–6 块，只剩 2–3 块余额**。
→ **数学元素（曲线、向量、场线、网格、矩形、刻度）一律白或灰**，紫只保留给**唯一一处「当前重点」实心图元**（动点 / 当前矩形 / 当前向量）。
→ 数学曲线要发光就用**白光晕**；用 `Plot glow` 得到的是紫光晕，会额外吃 1 块。
→ 不要同时开「大字紫硬投影 + 紫实心图元 + 紫发光曲线」。

**实测验证**：函数图像原型去掉紫色小字后，紫碎片 **8 → 7**，判定由 `低:紫色碎片≥8` 转 **OK**。

### 规则 3：「光跟主角」在判据上是硬性的

`主角区柔光` 量的**不是**"画面有没有光"，而是**最大物体包围盒外扩 30px 内的最大柔光连通块**。
→ **光必须覆盖主体尺度最大的那个物体**，否则画面再亮也判 `低:主角无光(<800px²)`。
→ 反面实测：向量场原型（最大物体是场，141px）把 `HeroGlow` 放在右侧大字上 → 主角区柔光仅 **896**（擦线，换个布局就跌破 800）。
→ 正确做法：**先确定谁是最大物体，再把 `HeroGlow` 覆盖它的包围盒**。

### 规则 4：安静是允许的（上游新规，2026-09-17）

`composition-and-light.md` §7 已改为：**最长静止 ≤3.0s**、静止**占比只报不判**，且明文「**不为凑指标给静止的物体加漂浮、飘动、呼吸**」。
→ 数学镜头**不需要**为动效指标给曲线/坐标系加无意义浮动；动作只来自语义（动点移动、矩形加密、光点沿导线跑、割线收拢、波前推进）。
→ 同时要满足**末拍停留 30–45 帧**（落位后稳定期），离场起点 ≥ 落位帧+30、运镜结束 ≤ 离场起点−30。

## 4. 概念类型补充（接 `narration-storyboard.md` §4 的表）

| 概念类型 | 画法 | 主角 · 尺寸 · 光 | 备注 |
|---|---|---|---|
| 函数图像 | 坐标系 + 曲线 draw-on + 动点沿曲线 + 虚线投影到两轴 | **坐标系图卡 h≥372**（实测 481）或**当前值大数字 ≥96px**；紫只给动点 | 动点移动即「持续动作」 |
| 导数 / 切线 | 割线两端点随 Δx 收拢 → 切线浮现，标注 Δx 与斜率 | 斜率大数字 ≥96px + 紫硬投影 | `SecantTangent`；Δx 递减到 0 |
| 积分 / 面积 | 曲线下面积填充 + 黎曼矩形逐条加密 | 矩形条数大数字 ≥96px；**紫只给当前矩形一条** | `AreaFill` `activeRect` |
| 波形 / 相位 | 两三条正弦波叠加，标周期/振幅/相位差 | 合成振幅大数字 ≥96px | 相位差用 `SpanLabel` |
| 向量场 / 场 | 箭头阵（+ 大实体如点电荷圆、带电板） | **必须外挂**：点电荷圆 r≥95 或大数字；**光打在它身上** | 场本身当不了主角（实测 141） |
| 几何证明 | 多边形 + 角弧 + 等长刻度 + 全等标记 | 图形本身（高≥340，实测 370）+ `HeroGlow` | 结论用 `CText` 白/紫大字 |
| 电路 | 电源/电阻/电容 + 导线 + 光点沿导线跑 | 电路本体（高≥300，实测 313）或电流大数字 | 元件需手画（未抽图元） |
| 公式推导 | `MathFormula` 逐条揭示（`MathFormulaReveal` wipe） | 结果项 **ink ≥72px**（fontSize ≥28 嵌套 / ≥60 单层） | 紫只给"当前这一步" |
| 量级 / 阈值 | 大数字 + 单位 + 对照物 | 沿用既有「大数字型高光时刻」 | 与概念题材一致 |

## 5. QC 判据对照（数学题材最容易撞的）

| 判据 | 阈值 | 数学题材的撞法 | 合法化 |
|---|---|---|---|
| 空场 | 连续 >45 帧无 ≥110px 主体且柔光 <10000px² | 细曲线 + 细坐标轴长时间无主体 | 坐标系图卡 h≥372 / 外挂大数字 |
| 主角尺寸 | 中位 <170px → 低 | 向量场、场线、单符号（实测 141） | 外挂大实体或多位数字大字 |
| 主角无光 | 主角区柔光中位 <800px² | 光没打在最物体上（实测 896 擦线） | `HeroGlow` 覆盖最大物体包围盒 |
| 紫色碎片 | ≥8 → 低 | 紫发光曲线 + 紫曲线 + 紫小字 + 高不透明紫 drop-shadow，叠加必超（实测一路到 15） | 数学元素全白/灰，紫只留 1 处实心；**发光用低透明度柔光（`HeroGlow`）或白光晕，不要用 `drop-shadow(...rgba(102,45,248,.85))`**（见规则 2） |
| 最小字号 | <22px | 刻度字、轴名、图注写小 | 全用 ≥22（图元库默认 22） |
| 静止 | 最长 >3.0s → 中 | 静态坐标系挂着不动 | 给语义动作（动点/加密/光点）；**不要加无意义漂浮** |
| 末拍停留 | <30 帧 → 中 | 推导到末拍就切 | 落位后留 30–45 帧 |

## 6. `examples/contrast/` 两条反例的改判
