## 质检

### 帧数匹配（12/12 通过）

每场景实际渲染帧数与分镜表声明区间对比，`TimedScene.check_frame_budget()`
自动核对。最终 **12/12 精确匹配**（DP06/DP10/DP11 差 1 帧，浮点取整，可接受）。

### 静止 QC（三层判据，见 `backends/manim/reference/qc-criteria.md`）

`core/motion_check.py` 的 320×180 降采样口径对 manim 内容**系统性偏严**：

| DP | 降采样报 | 全分辨率 | 真相 |
|---|---|---|---|
| DP01 | 7.0s | 7.1s | 误报——走山人质心 (517,340)→(590,350) 持续移动 |
| DP06 | 6.1s | 6.2s | 误报——箭头连续转向 80 帧 |
| DP09 | **9.6s** | **4.0s** | **降采样严重误报**（三个小球演示被完全抹掉） |
| DP11 | 9.1s | 6.2s | 误报——短轴箭头扫动 40 帧 |
| DP12 | 7.4s | 5.4s | 误报——小球 9 步迭代 360 帧 |

**结论**：manim 推导片的运动语言是"小幅度连续运动"（点沿线走、箭头转向、
公式逐 token 出现），与 remotion MG 片的"大面积 × 实心 × 快"不同。
降采样口径不可作为唯一判据，必须用全分辨率 + 质心追踪确认。

### 公式可见性

`media/tex/*.svg` 的 `use` 引用数 = `defs` 定义数（字体完整嵌入）。
中文标注一律走 `common.plain()`（`Text`），不进 LaTeX
（`\text{中文}` 会报 `Unicode character 步 (U+6B65)`）。

## 已知保留项

1. **`--still-max 5.0` 是设计推断**：本样片用全分辨率 QC 校准过，
   但 5.0 这个具体值没有第二部片子交叉验证。下一部 manim 片应重新校准。
2. **DP03 全分辨率 5.5s 静止**：纯公式展示（`Δθ = η × g` + 两句说明），
   没有可加的运动会自然。若严格按 5s 判，这是唯一真实的边界案例。
3. **片头无章节卡/片尾**：manim 端 V1 未实现覆盖层（片头 LEAD 45 帧是黑屏 +
   字幕）。这是与 remotion 后端的明显差距，留 V3。

## 制作过程（可复现）

```bash
# 1. 建项目

# 2. 解说词 → 时间轴（注意：core/tts_build.py 的 argv bug 已修）

# 3. 分镜令牌 → 帧号
.venv/bin/python scripts/render_storyboard.py

# 4. 多 Scene 字幕对齐
.venv/bin/python scripts/gen_frame_offsets.py

# 5. 单场景测渲（-qm -r 480,270，帧率保持 30）
zsh scripts/test_render.sh DP01

# 6. 整片
VER=v1 zsh scripts/render.sh

# 7. QC
.venv/bin/python scripts/motion_check.py --frames fin_frames --shots DP01:86-385,... --still-max 5.0 --no-hold
```
